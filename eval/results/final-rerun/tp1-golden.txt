tp1 golden-token identity gate against upstream feaf4dd
=======================================================
Recorded 2026-08-29.

Why this exists
---------------
scripts/tp1-regression.sh was described as a "byte-identity gate" but originally had no upstream
baseline: it asserted only that a single-GPU run still produced a counting sequence and the right
identity rows. That could not have detected a token-level drift. This run establishes the missing
baseline.

Method
------
Upstream feaf4dd was built from a detached git worktree of this repository
(`git worktree add --detach <dir> feaf4dd`) with the same generator, build type and toolchain as the
fork's build:

  cmake -S <dir> -B <dir>/build -G Ninja -DCMAKE_BUILD_TYPE=Release \
        -DCMAKE_CUDA_COMPILER=/usr/local/cuda-13.1/bin/nvcc
  cmake --build <dir>/build -j
  -> 278/278 targets, apps/ninfer linked

Upstream feaf4dd's CLI accepts --print-token-ids, --greedy and --no-thinking, so this is a
TOKEN-ID comparison, not a decoded-text-only one.

Both binaries then ran the same recorder over the same three prompts, back to back, GPU 0 with no
other compute process resident:

  tests/data/tp1-golden/record.sh <binary> \
    /home/pc/models/ninfer-38/huihui-nvfp4/qwen3_8_27b_nvfp4.ninfer <outdir>

which runs, for each case:

  CUDA_DEVICE_ORDER=PCI_BUS_ID CUDA_VISIBLE_DEVICES=0 <binary> <artifact> \
    --messages <case>.json <per-case flags> \
    --max-new 128 --greedy --no-thinking --print-token-ids

  case 1 short chat     23 prompt tokens   --max-context 4096
  case 2 instruction  2,191 prompt tokens  --max-context 4096
  case 3 document    28,677 prompt tokens  --max-context 32768 --kv-dtype int8

The fork ran at its defaults, which are the tp1-equivalent ones: --tp 1, --rope native. Prompts are
generated by tests/data/tp1-golden/make_prompts.py (fixed LCG over a fixed word list, ASCII, no
clock) so the inputs are reproducible from a rule rather than a checked-in blob.

Environment: one RTX 5090 (sm_120a), CUDA 13.1, driver 580.178.04, artifact qwen3_8_27b / nvfp4,
18.99 GiB as read.

Result
------
BYTE-IDENTICAL on every compared file, all three cases. `diff -r` between the two recorded
directories is empty:

  case-1  72 generated token ids   ids + text + summary identical
  case-2 128 generated token ids   ids + text + summary identical
  case-3  98 generated token ids   ids + text + summary identical

(cases 1 and 3 stop on the end-of-turn token before the 128-token limit.)

One summary row had to be excluded as non-deterministic rather than as a fork-vs-upstream
difference: `CUDA Graph memory` is the driver's own accounting of the instantiated graphs and it
moved across three consecutive identical runs of ONE binary (2.12 / 2.00 / 2.00 MiB). The other
exclusions are wall-clock rows, the three free-memory rows (they track whatever else is resident on
the GPU), and the rows this fork added that upstream does not print (`tensor parallel`, `rope`,
`gpu0 *`). Everything else -- artifact read size, weight H2D, tensor/resource counts, sampling mode,
finish reason, prompt/reused/generated token counts, device, max context, KV capacity policy and
capacity, KV page groups, KV dtype and payload, gpu weights/sequence used, workspace peak, runtime
reservation, planned device total -- matched exactly.

Gate
----
scripts/tp1-regression.sh now re-records the three cases with the working build and requires byte
equality against tests/data/tp1-golden/case-N.{ids,txt,summary}. Full run after the change:

  TP1-REGRESSION: golden gate PASS (3 cases, ids + text + summary byte-equal)
  TP1-REGRESSION: PASS
  identity OK (target=qwen3_8_27b, weights=nvfp4)
  real 42.5 s

Scope
-----
Greedy text decode at --tp 1 / --rope native on qwen3.8-27b/nvfp4, MTP off, concurrency 1, over a
short, a 2k and a 29k prefill. It does not cover sampled decoding, Vision, MTP, groupwise-int, the
35B-A3B target, or concurrency > 1; for those, tp1 identity rests on the `cuobjdump -sass`
comparison of the rope kernels (all 21 native kernels byte-identical, so the native path is
unchanged instruction for instruction) and on the tp2 parity harness's null control.

The upstream worktree was removed after recording; re-establishing the baseline is one
`git worktree add` plus one `record.sh` invocation.
